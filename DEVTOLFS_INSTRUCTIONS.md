# 🛠 Руководство разработчика по отладке

Этот документ — для тех, кто сопровождает скрипт [`ozon-orders-copier.user.js`](ozon-orders-copier.user.js).
Здесь описано, **почему скрипт может ломаться**, как работает встроенная диагностика и **что делать пошагово**, если вы заметили проблему (пропали заказы, неверные статусы, пустые поля и т. п.).

---

## Почему скрипт вообще ломается

Ozon — динамический сайт с регулярными обновлениями вёрстки. Скрипт извлекает данные о заказах, и для устойчивости к редизайнам используется двухуровневая стратегия парсинга:

1. **JSON-first** — данные берутся напрямую из внутреннего состояния страницы (`state-orderList → ordersV2`). Это **не зависит** от CSS-классов и работает всегда, пока Ozon рендерит страницу.
2. **DOM-fallback** — если JSON недоступен, скрипт ищет карточки заказов в DOM по набору известных CSS-селекторов и структурно (по ссылкам на `orderdetails`).

Тем не менее полностью застраховаться нельзя: Ozon может изменить структуру JSON, переименовать поля (`badgeStatus`, `price`, `picture` и т. д.) или поменять разметку страниц деталей заказа. В таких случаях часть данных перестаёт извлекаться — это и есть «поломка».

> ⚠️ **Главный принцип отладки:** не чинить вслепую. Сначала собрать **диагностический отчёт**, понять, какой именно этап упал, и только потом менять код.

## 🔬 Встроенная диагностика

В правом нижнем углу страницы [Мои заказы](https://www.ozon.ru/my/orderlist) есть фиолетовая кнопка **🔬 Диагностика**.

Она запускает обычный парсинг с включённым сборщиком телеметрии, а затем формирует **единый Markdown-файл** со всеми сырыми данными — без обрезки. Файл сохраняется в загрузки браузера под именем:

```
Ozon_Диагностика_YYYY-MM-DD-HH-MM-SS.md
```

### Что внутри отчёта (8 секций)

| # | Секция | Зачем нужна |
|---|---|---|
| 1 | 🖥 **Окружение** | User-Agent, URL, версия скрипта, время, размер окна — контекст воспроизведения |
| 2 | 📊 **Итоги сбора** | Сколько заказов найдено, сколько ошибок, снимков и т. д. — общая сводка |
| 3 | 🔎 **DOM-пробы** | Какие CSS-селекторы сработали для пункта выдачи (pickupPoint / detailsAddress), а какие — нет. **Ключ к обновлению логики адреса** |
| 4 | 🔀 **Diff парсинга** | Для каждого поля: ожидаемый путь в JSON/DOM → фактическое значение → `OK`/`FAIL`. Показывает, какое поле перестало извлекаться |
| 5 | ❗ **Ошибки** | Агрегированный лог: заказ → этап → сырые данные → текст ошибки |
| 6 | 📦 **Сырые данные** | Полные `cardHTML`, `state-orderList` JSON, `shipmentWidgets` JSON (без обрезки) |
| 7 | 📄 **Снимки orderdetails** | Полный HTML страниц деталей заказов (до 200 КБ на заказ) |
| 8 | 🖼 **Фото** | Лог загрузки и вставки изображений: URL → HTTP-статус → байты → результат |

Отчёт самодокументируем: каждая секция содержит пояснения, а статус `OK`/`FAIL` сразу подсвечивает проблемные места.

## 🚨 Что делать, если заметили проблему

### Шаг 1. Воспроизведите проблему

1. Авторизуйтесь на [ozon.ru](https://www.ozon.ru) под нужной учётной записью
2. Откройте **[https://www.ozon.ru/my/orderlist](https://www.ozon.ru/my/orderlist)**
3. Убедитесь, что список заказов виден на странице

### Шаг 2. Соберите диагностический отчёт

Нажмите кнопку **🔬 Диагностика**. Скрипт:
- пройдёт по всем заказам с включённой телеметрией,
- подгрузит детали каждого заказа (`/my/orderdetails/`),
- соберёт markdown и скачает файл `Ozon_Диагностика_*.md` в папку загрузок.

Дождитесь надписи **✅ Отчёт скачан** на кнопке.

### Шаг 3. Положите отчёт в проект

Скопируйте скачанный `.md`-файл в локальную папку [`diagn/`](diagn/) этого репозитория:

```
ozon-order-excel-exporter/
└── diagn/
    └── Ozon_Диагностика_2026-07-30-12-56-18.md   ← сюда
```

> 📌 Папка `diagn/` добавлена в `.gitignore` — диагностические дампы содержат **ваши персональные данные** (адреса, номера заказов, товары) и **не должны попадать в git/GitHub**. Они остаются только у вас локально.

### Шаг 4. Проанализируйте отчёт с помощью LLM-плагина

Откройте проект в редакторе с AI-ассистентом (например, VS Code с плагином-агентом: Cline, Roo, Continue и т. п.) и попросите:

1. **Прочитать диагностический отчёт** в `diagn/Ozon_Диагностика_*.md`
2. **Прочитать код** скрипта [`ozon-orders-copier.user.js`](ozon-orders-copier.user.js)
3. **Найти причину** и предложить точечное исправление

LLM увидит и реальную разметку/JSON (из секций 3, 4, 6, 7 отчёта), и текущую логику парсинга (в коде), поэтому сможет указать, какой именно путь извлечения сломался и как его обновить.

#### Пример запроса к ассистенту

```
В папке diagn/ лежит диагностический отчёт Ozon_Диагностика_*.md.
В разделе «4. Diff парсинга» найди поля со статусом FAIL — это то,
что перестало извлекаться после обновления Ozon.
Сравни ожидаемые пути с реальной структурой в разделах
«3. DOM-пробы» и «6. Сырые данные» и обнови логику парсинга
в ozon-orders-copier.user.js, чтобы поля снова заполнялись.
```

### Шаг 5. Проверьте исправление

После внесения правок обновите скрипт в Tampermonkey, перезагрузите страницу заказов и снова нажмите **🔬 Диагностика** — в новом отчёте в секции 4 проблемные поля должны стать `OK`.

### Шаг 6. Уберите за собой

После исправления удалите диагностический файл из `diagn/` — он больше не нужен и содержит персональные данные.

## 💡 Советы по чтению отчёта

- **Начинайте с секции 2 (Итоги)** — если «Найдено заказов = 0», значит сломался顶层-парсинг (`parseOrdersFromStateJSON` + DOM-fallback). Если заказы есть, но поля пустые — сломалось извлечение конкретных полей.
- **Секция 4 (Diff парсинга)** — самый быстрый способ найти проблему. Ищите строки `FAIL` — это поля, которые скрипт не смог заполнить.
- **Секция 3 (DOM-пробы)** — если адрес пункта выдачи пустой, смотрите, какой селектор реально сработал на странице, и обновите каскад селекторов в `fetchOrderDetails` / `parseOrder`.
- **Секция 6 (Сырые данные)** — если структура JSON изменилась (например, поле `badgeStatus` переименовали), это будет видно здесь. Сверяйтесь с путями в коде (`extractPaymentFromOrderListJSON`, `parseOrdersFromStateJSON`).

## 🔒 Приватность

Диагностический отчёт содержит **ваши персональные данные**: номера заказов, адреса пунктов выдачи, названия товаров, цены. Поэтому:

- ✅ Файл остаётся **только локально** в `diagn/` (папка в `.gitignore`)
- ❌ **Никогда** не коммитьте файлы из `diagn/` и не выкладывайте их в issue/PR
- ❌ **Никогда** не отправляйте отчёт третьим лицам без удаления персональных данных
